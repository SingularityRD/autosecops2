### Repairing an existing install by hand (finding #2)

Use this only if you cannot upgrade to a chart that includes the self-heal. Run it as the chart's database user (the owner of `_vigil_schema_versions`) once the backend has started at least once, so `cases` exists:

```sql
DELETE FROM _vigil_schema_versions
 WHERE filename IN ('50_regulatory_clocks.sql',
                    '58_broadcast_unique_and_clock_heads.sql');
```

Then run `helm upgrade` (staging included). The db-init Job re-applies both files. To check: `SELECT to_regclass('regulatory_clock_events'), to_regclass('regulatory_report_drafts'), to_regclass('regulatory_clock_heads');` must return three non-null values.
