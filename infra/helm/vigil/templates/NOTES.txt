Vigil SOC has been installed in namespace {{ .Release.Namespace }} as release "{{ .Release.Name }}".

1. Wait for pods to come up:

   kubectl get pods -n {{ .Release.Namespace }} -l app.kubernetes.io/instance={{ .Release.Name }} -w

2. The db-init Job runs once per install/upgrade. Check its status:

   kubectl get jobs -n {{ .Release.Namespace }} -l app.kubernetes.io/component=db-init

3. Access the backend API:

{{- if .Values.ingress.enabled }}
   Ingress is enabled. Point DNS at your ingress controller and visit:
{{- range .Values.ingress.hosts }}
     http{{ if $.Values.ingress.tls }}s{{ end }}://{{ .host }}
{{- end }}
{{- else }}
   kubectl port-forward -n {{ .Release.Namespace }} svc/{{ include "vigil.backend.fullname" . }} {{ .Values.backend.service.port }}:{{ .Values.backend.service.port }}
   # Then open http://localhost:{{ .Values.backend.service.port }}
{{- end }}

SIGNING KEYS: audit checkpoints and evidence packs are signed with the keys in
   {{ include "vigil.signingKeys.secretName" (dict "context" . "key" "AUDIT_CHECKPOINT_SIGNING_KEY") }} and {{ include "vigil.signingKeys.secretName" (dict "context" . "key" "EVIDENCE_PACK_SIGNING_KEY") }}.
   Give whoever verifies offline the public halves (no private key is printed):

   and evidence packs carry a one-off key. /api/health lists the warning.

{{- if not .Values.evidence.persistence.enabled }}

⚠️  EVIDENCE IS NOT PERSISTENT: evidence.persistence.enabled is false, so files
   attached to cases (the /hunt document and other evidence) are written to the
   State Directory volume ({{ if hasKey .Values.stateDirectory.volume "emptyDir" }}an emptyDir{{ else }}stateDirectory.volume{{ end }}) and, with an emptyDir, are LOST on
   every pod restart and exist only on the pod that took them. Their database
   rows survive and point at files that are gone. For any install that keeps
   evidence set evidence.persistence.enabled=true,
   evidence.persistence.accessModes={ReadWriteMany} and an RWX
   evidence.persistence.storageClassName (or existingClaim).
{{- else if include "vigil.evidence.rwxOnDefaultClass" . }}

⚠️  EVIDENCE STORE: this release creates the case evidence claim
   {{ include "vigil.evidence.claimName" . }} as ReadWriteMany on the cluster's DEFAULT
   StorageClass. If that class cannot provide ReadWriteMany (most block,
   local-path and hostPath classes cannot), the claim stays Pending and the
   backend, daemon and llm-worker pods never start. Check with:

     kubectl get pvc -n {{ .Release.Namespace }} {{ include "vigil.evidence.claimName" . }}

   Fix: evidence.persistence.storageClassName=<an RWX class>, or
   evidence.persistence.existingClaim=<your claim>.
{{- end }}

4. Run the smoke test:

   helm test {{ .Release.Name }} -n {{ .Release.Namespace }}

{{- if eq (.Values.config.DEV_MODE | toString) "true" }}

⚠️  WARNING: DEV_MODE is enabled. Authentication is BYPASSED and every request
   acts as a mock admin user. Do NOT expose this deployment publicly. Flip
   config.DEV_MODE to "false" and set secrets.jwtSecretKey to enable real auth.
{{- else }}

No default admin account ships. On first visit the web UI opens a bootstrap
screen (POST /api/auth/bootstrap) where you create the admin with a password
of your choosing; it closes as soon as one account exists.

Creating that first admin needs the one-time setup token, so whoever reaches
the instance first cannot claim it.
{{- if .Values.secrets.setupToken }}
It is the value you set in secrets.setupToken.
{{- else }}
The backend prints it once, on first start. Read it with:

   kubectl logs -n {{ .Release.Namespace }} -l app.kubernetes.io/instance={{ .Release.Name }},app.kubernetes.io/component=backend --prefix --tail=-1 | grep "setup token"
{{- end }}

Or issue a new one (the old one stops working) with:

   kubectl exec -n {{ .Release.Namespace }} deploy/{{ include "vigil.backend.fullname" . }} -c backend -- python -m core.auth.setup_token regenerate
{{- end }}

{{- $user := dig "gateway" "viewer" "username" "<medic.gateway.viewer.username>" $medic }}
{{- $secret := dig "gateway" "viewer" "passwordSecret" "name" "<passwordSecret.name>" $medic }}

Medic is on. Once the backend is up, create its gateway's Viewer service account
(lockout-exempt, Viewer only; docs/medic/enable.md). The password goes from the
Secret to the backend on a pipe, never on a command line. Re-run after changing
the Secret to rotate, then restart the gateway:

   kubectl -n {{ .Release.Namespace }} get secret {{ $secret }} -o jsonpath='{.data.{{ $key }}}' | base64 -d \
     | kubectl -n {{ .Release.Namespace }} exec -i deploy/{{ include "vigil.backend.fullname" . }} -- \
         python -m core.auth.service_account ensure {{ $user }}
{{- end }}
